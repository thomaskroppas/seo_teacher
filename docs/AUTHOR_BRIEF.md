# Бриф автору модуля

Ты автор самого понятного русскоязычного курса по SEO **для людей с нуля**. Репозиторий: /home/user/seo_teacher.

1. Прочитай ПОЛНОСТЬЮ `docs/CONTENT_SPEC.md` — портрет ученика, формат, правила простоты и учебный план. Это главный документ; нарушать границы уроков нельзя.
2. Для фактов можно использовать старые «профессиональные» модули в `archive/pro/module-N.js` (подсказка о соответствии — в твоём задании). Это **источник фактов, а не образец стиля**: они написаны для профи и слишком длинные. Переписывай с нуля простым языком, короче, с аналогиями, **не копируй** жаргонные куски. Если нужны проверенные факты 2025–2026 — можно использовать WebSearch/WebFetch (по желанию).
3. Пиши модуль в файл `data/module-N.js` (N — номер модуля из задания). Файл большой: **собирай по частям в своей личной папке** `/tmp/claude-0/-home-user-seo-teacher/66153601-d0e2-5923-bed4-eb110e2bd241/scratchpad/mN-own/` (N — твой номер; другие агенты работают параллельно, **не используй общие имена файлов и не пиши в чужие папки**), потом собери итоговый файл в `data/module-N.js` (например, `cat head.js l1.js ... tail.js > data/module-N.js` или одним `node`-скриптом с JSON.stringify). Внимательно следи за синтаксисом template literal: экранируй обратные кавычки и `${`.
4. Проверь: `node scripts/validate.js data/module-N.js` — исправь ВСЕ ошибки и предупреждения (теория 380–1000 слов на урок, 20–40 минут, 5–6 вопросов квиза, 4–6 карточек, ровно 4 сценария, 10 вопросов экзамена).
5. Не трогай другие файлы, не делай git commit. Перед завершением перечитай 1–2 своих урока глазами новичка: нет ли непонятных слов без объяснения, не слишком ли сухо, не слишком ли длинно.
6. Финальное сообщение — одна-две строки: итог валидации и что стоит перепроверить (факты, цены, ссылки).
