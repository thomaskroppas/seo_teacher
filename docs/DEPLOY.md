# Развёртывание SEO-обучателя: сайт на reg.ru + ИИ-наставник

## Как это устроено

```
Телефон / компьютер ──HTTPS──▶ Ваш сайт на reg.ru (PHP + SQLite)
 (приложение/браузер)            · вход, роли «ученик» / «админ»
                                 · прогресс каждого ученика (изолирован)
                                 · лимит ИИ $/сутки и учёт расходов
                                         │  (только вопрос ученика + текст урока)
                                         ▼
                                Ретранслятор за границей (Vercel, бесплатно)
                                 · хранит ключ OpenAI
                                         ▼
                                      OpenAI API
```

* **Сайт и база** — на вашем shared-хостинге reg.ru. Ничего, кроме PHP, не нужно. База — один файл SQLite *вне* папки сайта.
* **Ключ OpenAI** лежит только в ретрансляторе (переменная окружения). Ни ученики, ни хостинг reg.ru его не видят.
* **Зачем ретранслятор.** Серверы reg.ru в России, а OpenAI не принимает API-запросы из России (ответ `403 Country, region, or territory not supported`). Поэтому запрос к OpenAI делает небольшая функция за границей.

> ⚠️ **Важно про правила OpenAI.** OpenAI официально не поддерживает доступ к API из России, а использование API в неподдерживаемой стране может привести к блокировке аккаунта. Если вы и ваши ученики находитесь в РФ, то ретранслятор — это обход этого ограничения, и риск блокировки аккаунта/ключа на вас. Если же аккаунт OpenAI и пользователи находятся в поддерживаемых странах, а в РФ только хостинг сайта, схема штатная. Альтернатива: указать в ретрансляторе другой OpenAI-совместимый сервис (переменная `OPENAI_BASE_URL`), доступный в вашем регионе, и сменить модель в админке.

## Что понадобится

1. Аккаунт **OpenAI** с ключом API и положительным балансом.
2. Аккаунт **GitHub** (у вас есть) и бесплатный аккаунт **Vercel** (вход через GitHub).
3. Хостинг **reg.ru** с PHP 8.0+ (лучше 8.2), расширениями `pdo_sqlite`, `curl`, `mbstring` (обычно включены), доступом по SSH и включённым HTTPS-сертификатом для домена.
4. Домен или поддомен для курса (например `seo.вашдомен.ru`).

## Шаг 1. Ретранслятор (Vercel)

1. Придумайте длинный секрет — **RELAY_SECRET** (32+ случайных символа). В SSH-консоли: `openssl rand -hex 32`. Сохраните его в менеджере паролей, он понадобится ещё раз на шаге 2.
2. Откройте vercel.com → войдите через GitHub → **Add New… → Project** → выберите репозиторий `seo_teacher` → **Import**.
3. В настройках импорта:
   * **Root Directory** → `relay` (Edit → выбрать папку relay);
   * **Framework Preset** → *Other*;
   * **Environment Variables** — добавьте:

   | Имя | Значение |
   |---|---|
   | `RELAY_SECRET` | секрет из п. 1 |
   | `OPENAI_API_KEY` | ваш ключ `sk-…` |
   | `ALLOWED_MODELS` | `gpt-6-sol,gpt-6-luna` (необязательно: ограничивает, какие модели можно вызвать) |
   | `MAX_TOKENS_CAP` | `4000` (необязательно: потолок длины ответа) |

4. **Deploy**. Через минуту получите адрес вида `https://seo-relay-xxxx.vercel.app`.
5. Проверка (в SSH-консоли или любом терминале):
   ```bash
   curl -s -H "X-Relay-Secret: ВАШ_СЕКРЕТ" "https://seo-relay-xxxx.vercel.app/api/relay?check=1"
   ```
   Должно быть `"ok":true`. Если `openai_status` 401 — неверный ключ; 403 «region» — регион ретранслятора не принят (в `relay/vercel.json` поменяйте `"fra1"` на другой регион, например `"iad1"`, и задеплойте заново).

*Вместо Vercel можно запустить `relay/server.js` на любом VPS за границей:* `RELAY_SECRET=… OPENAI_API_KEY=… PORT=8787 node relay/server.js` (за nginx с HTTPS).

## Шаг 2. Сайт на reg.ru

### 2.1. Подготовка
1. В панели хостинга создайте сайт для домена/поддомена (корень будет `~/www/ВАШ_ДОМЕН/`) и включите бесплатный SSL (Let's Encrypt). Убедитесь, что сайт открывается по `https://`.
2. В настройках PHP для этого сайта выберите версию **8.1 или новее** (раздел «PHP» / «Настройки PHP»; название может отличаться).

### 2.2. Загрузка файлов (способ А — через git, как вы уже делаете)
В SSH-консоли панели:
```bash
cd ~/www/ВАШ_ДОМЕН            # папка должна быть пустой (удалите index.html-заглушку)
git clone https://github.com/thomaskroppas/seo_teacher .
```
Если репозиторий приватный, создайте на GitHub *Personal access token* (Settings → Developer settings → Fine-grained tokens, доступ «Contents: read» к этому репозиторию) и клонируйте так: `git clone https://ВАШ_ТОКЕН@github.com/thomaskroppas/seo_teacher .`

*Способ Б:* на GitHub нажмите **Code → Download ZIP**, загрузите архив через файловый менеджер панели в `~/www/ВАШ_ДОМЕН/` и распакуйте так, чтобы `index.html` лежал прямо в корне сайта.

### 2.3. Папка для базы данных (вне сайта!)
```bash
mkdir -p ~/seo_data && chmod 700 ~/seo_data
echo ~/seo_data               # запомните полный путь, например /home/u1234567/seo_data
```

### 2.4. Конфигурация
```bash
cd ~/www/ВАШ_ДОМЕН/api
cp config.sample.php config.php
nano config.php               # или правка через файловый менеджер
```
Заполните:
* `data_dir` — путь из п. 2.3;
* `setup_key` — придумайте длинную случайную строку (нужна один раз, чтобы создать администратора);
* `relay_url` — `https://seo-relay-xxxx.vercel.app/api/relay`;
* `relay_secret` — тот же секрет, что `RELAY_SECRET` на Vercel;
* `timezone` — `Europe/Moscow` (по нему считаются «сутки» лимита).

> Файл `config.php` не попадает в git (он в `.gitignore`) — секреты остаются только на сервере.

### 2.5. Проверка окружения
Откройте в браузере (подставьте домен и свой `setup_key`):
```
https://ВАШ_ДОМЕН/api/index.php?a=diag&key=ВАШ_SETUP_KEY
```
Должно быть: `"pdo_sqlite": true`, `"curl": true`, `"db_ok": true`, `"https": true`, `"relay_http": 200` и в `relay_reply` — `"ok":true`. Если что-то иное — см. «Если не работает».

### 2.6. Первый вход
Откройте `https://ВАШ_ДОМЕН/` → появится форма «Первый запуск». Введите `setup_key`, логин, имя и пароль (от 8 символов) — вы станете **администратором**. Форма больше не появится.

## Шаг 3. Настройка в приложении («Админ»)

1. **Админ → ИИ и лимиты.** Выберите модель кнопкой **Sol** или **Luna** (или впишите идентификатор вручную) и **сверьте цены** с openai.com/api/pricing — по ним считаются расходы. Лимит ученика по умолчанию — **$1/сутки**, общий лимит всех — $5/сутки (можно менять). «Проверить подключение к ИИ» покажет, достучался ли сервер до ретранслятора.
2. **Админ → Ученики → Создать.** Задайте логин, пароль (кнопка «Сгенерировать пароль»), при желании индивидуальный лимит. Передайте данные ученику лично; сменить пароль он сможет в «⚙ Настройки».
3. Лимит конкретного ученика поднимается в таблице учеников (поле «Лимит $/сутки» → OK). Обычный ученик повысить лимит не может — проверяется на сервере.

**Как работает лимит.** Перед каждым запросом сервер оценивает его максимальную стоимость и не пропускает, если сумма за сутки превысит лимит. После ответа списывается фактическая стоимость по `usage` из ответа API. Один ученик — один запрос одновременно. Ученик видит «Сегодня потрачено $X из $Y» в окне чата. Сутки считаются по часовому поясу из `config.php`.

*Ориентир по расходу:* один ответ с текстом урока в контексте — примерно 5–10 тыс. входных и 300–800 выходных токенов. По ценам Sol ($2/$10 за 1 млн) это около $0.015–0.03, то есть $1/сутки ≈ 30–60 ответов. Luna в ~20 раз дешевле. Если цены в настройках не совпадают с реальными, лимит будет неточным — сверяйте.

> Дополнительная страховка: в кабинете OpenAI (Billing → Limits) задайте месячный лимит расходов и отдельный ключ только для этого проекта.

## Шаг 4. Установка как приложения

* **iPhone / iPad:** откройте сайт в **Safari** → кнопка «Поделиться» → **«На экран „Домой“»** → Добавить. Иконка появится на рабочем столе, приложение откроется без адресной строки. (Внутри установленного приложения войдите заново: у Safari и «приложения» на iOS раздельные сессии. Прогресс подтянется с сервера.)
* **Android:** откройте сайт в **Chrome** → меню ⋮ → **«Установить приложение»** (или «Добавить на главный экран»).
* **Компьютер:** в Chrome/Edge в адресной строке значок «Установить».

Обновления приезжают сами: приложение сначала берёт свежие файлы с сайта и только без сети использует сохранённую копию. Чтение уроков офлайн работает; вход, синхронизация и ИИ требуют интернета.

## Обновление и резервные копии

* **Обновить сайт:** `cd ~/www/ВАШ_ДОМЕН && git pull` (перезапускать ничего не нужно — это PHP). База и `config.php` при этом не затрагиваются. Ученикам достаточно закрыть и снова открыть приложение.
* **Резервная копия базы** (аккаунты, прогресс, расходы — один файл): `cp ~/seo_data/app.sqlite ~/seo_backup-$(date +%F).sqlite`. Раз в сутки можно настроить через cron в панели: `cp ~/seo_data/app.sqlite ~/seo_data/backup-$(date +\%u).sqlite` (хранит 7 последних дней).
* **Сменить секрет ретранслятора:** замените `RELAY_SECRET` на Vercel (Settings → Environment Variables → Redeploy) и `relay_secret` в `api/config.php`.

## Если не работает

| Симптом | Причина и решение |
|---|---|
| В diag: `data_dir внутри веб-каталога` | Укажите `data_dir` выше папки сайта, например `~/seo_data` (п. 2.3). |
| `pdo_sqlite: false` | Включите SQLite/PDO в настройках PHP хостинга или напишите в поддержку reg.ru. |
| `Внутренняя ошибка сервера` | Временно поставьте `'debug' => true` в config.php, повторите действие, прочитайте сообщение, потом верните `false`. Логи PHP — в панели хостинга. |
| `Ретранслятор отклонил секрет` | `relay_secret` в config.php ≠ `RELAY_SECRET` на Vercel. |
| `OpenAI отклонил запрос … регион` | Регион ретранслятора не поддерживается: поменяйте `regions` в `relay/vercel.json` (см. шаг 1) или используйте другой хостинг для ретранслятора. |
| `У OpenAI закончился баланс или превышен лимит` | Пополните баланс OpenAI / проверьте лимиты в кабинете OpenAI. |
| `Модель не найдена` | Админ → ИИ и лимиты: проверьте идентификатор модели (доступность зависит от вашего ключа). |
| `Сервер ретрансляции недоступен` | Проверьте `relay_url`; с хостинга reg.ru проверьте `curl -I https://…vercel.app` в SSH. Если Vercel недоступен с хостинга, разверните ретранслятор на VPS. |
| Ответ ИИ приходит сразу целиком, а не по буквам | Хостинг буферизует вывод. Это не ошибка: работает так же, просто без «печати». |
| «Слишком много попыток» при входе | 6 неверных паролей подряд блокируют вход для логина на 15 минут. |
| Ученик не может войти / ему «не хватает прав» | Админ → Ученики: проверьте, что аккаунт не отключён, при необходимости задайте новый пароль. |
| Забыли пароль администратора | В SSH: удалите файл базы **только если нет других данных**, либо создайте второго админа заранее. Резервная копия и второй администратор — лучшая страховка. |

## Безопасность — кратко

* Пароли хранятся в виде хэшей (bcrypt), сессии — в виде хэшей токенов, cookie `HttpOnly` + `SameSite=Lax` (+`Secure` на HTTPS).
* Каждый запрос ученика привязан к его аккаунту на сервере: чужой прогресс, чаты и расходы недоступны. Чаты хранятся только в прогрессе владельца; сервер не ведёт журнал текстов вопросов и ответов.
* Администраторские действия проверяются на сервере по роли из базы, а не по данным браузера.
* Лимиты и цены задаются только на сервере; подменить их из браузера нельзя.
* Ключ OpenAI живёт только в Vercel; на хостинге reg.ru лежит лишь общий секрет ретранслятора.
* Не публикуйте `api/config.php`, ключи и секреты в репозитории и чатах.
